模块采用客户端-服务端分离架构：
- 客户端侧（`config.py`、`clients.py`、`classical_methods.py`）：`CloudClassicalConfig` 集中管理 provider 配置与默认 endpoint；`TyxonQClassicalClient` 通过 `urllib` 向 `/classical/compute` 发送 JSON payload；`CloudClassicalMethodsWrapper` 暴露 PySCF 风格的 `fci/ccsd/dft/mp2/casscf` 等高层 API，内部将 `pyscf.gto.Mole` 序列化为 `molecule_data` 后交由 client 提交。
- 服务端侧（`server/`）：`app.py` 基于 FastAPI 暴露 POST `/classical/compute`，按 `classical_device` 字段路由到 `gpu_chem.compute` 或 `cpu_chem.compute`，GPU 失败时自动回退 CPU；`cpu_chem.py` 使用 PySCF 的 RHF/ROHF 作为统一 HF 基态并复用 chkfile；`gpu_chem.py` 通过可选的 `gpu4pyscf` 加速 SCF/MP2/DFT，CCSD 仍走 CPU 实现。
- 依赖方向单向：`classical_methods → clients → config`，`server/app → server/{cpu,gpu}_chem`，二者通过 HTTP JSON 协议解耦，便于本地 mock（`mock_classical_server.py`）与独立部署。
