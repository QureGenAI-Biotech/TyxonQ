模块按「Python 求解入口 → 可选 C++/CUDA 后端 → 共享验证」分层组织：
- 顶层 `torch_sci_solver.py` 实现基于本方 `torch_davidson` 的 A100 双精度求解，Hamiltonian/RDM 可切换为 `torch_selected_ci`（纯 PyTorch）或 `sbd_solver.SBDContractor`（C++ TPB），自旋惩罚走 `torch_spin_square`。
- `sbd_solver.py` 通过 `_load_extension()` 延迟加载已编译的 `_sbd_tpb_cuda` 扩展，暴露 `SBDContractor`（持有固定组态连接表、对角元、H@c、RDM）和 `solve_sci_sbd` 原生求解入口；MPI 多卡仅由独立基准直接调用扩展。
- `batch.py` 用 `multiprocessing.spawn` 启动每卡一个 worker 进程，通过 Queue 分发批次任务，统一包装 `solve_sci_cuda` / `solve_sci_sbd` 为 `make_cuda_sci_solver` / `make_sbd_sci_solver` 工厂。
- `sbd_ext/` 是可选构建子系统：`build.py` 从 pinned commit 下载 SBD 源码、校验 SHA256、应用 `nvcc.patch`，再用 nvcc + mpicxx 编译 pybind11 绑定 `tpb.cpp`，产物名 `_sbd_tpb_cuda`；`spin_kernels.cuh` 提供 CUDA 核函数，`SOURCES.json` 声明受信任文件清单。
- `validation.py` 被所有求解器共享，提供输入归一化、初猜投影、`independent_cpu_validation`（子进程隔离 PySCF）、失败快照 `validation_failure_snapshot` 及 RDM/自旋验收。
- `__init__.py` 使用 `__getattr__` 惰性导出 `solve_sci_cuda`，保证 import 不触发 PyTorch/CUDA 初始化。
依赖方向单向：batch → (torch_sci_solver | sbd_solver) → validation；sbd_ext 仅被 sbd_solver 在运行时导入。
